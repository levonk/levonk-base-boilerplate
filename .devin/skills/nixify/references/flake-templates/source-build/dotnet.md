# Source Build Flake: .NET / C# (buildDotnetModule)

Use when the project does not have published binary releases and uses the .NET
SDK (`dotnet`) with a `.csproj` or `.fsproj` project file.

**Skip if:** the project targets .NET Framework (Windows-only, not .NET
Core/5+), or uses a non-standard build system (e.g. custom MSBuild toolchain
outside the standard `dotnet build` / `dotnet publish` flow).

```nix
{
  description = "<Project description>";

  inputs = {
    nixpkgs.url = "github:NixOS/nixpkgs/nixpkgs-unstable";
    # Pin x86_64-darwin to a stable release branch for older macOS Intel
    # compatibility. See references/flake-templates/darwin-legacy-pin.md.
    nixpkgs-darwin-legacy.url = "github:NixOS/nixpkgs/nixpkgs-24.05-darwin";
    flake-utils.url = "github:numtide/flake-utils";
  };

  outputs = { self, nixpkgs, nixpkgs-darwin-legacy, flake-utils, ... }@inputs:
    flake-utils.lib.eachDefaultSystem (system:
      let
        pkgs =
          if system == "x86_64-darwin"
          then nixpkgs-darwin-legacy.legacyPackages.${system}
          else nixpkgs.legacyPackages.${system};
        <pname> = pkgs.buildDotnetModule {
          pname = "<binary-name>";
          version = "<x.y.z>";
          # cleanSource filters build artifacts, .git, .devbox, etc., so
          # trivial local changes do not invalidate the Nix build cache.
          src = pkgs.lib.cleanSource ./.;

          # Match the SDK major version to the project's TargetFramework:
          #   net6.x  → dotnet-sdk_6
          #   net7.x  → dotnet-sdk_7
          #   net8.x  → dotnet-sdk_8
          dotnet-sdk = pkgs.dotnet-sdk_8;
          dotnet-runtime = pkgs.dotnet-runtime_8;

          # NuGet lockfile generated by nuget-to-nix (see note below).
          nugetDeps = ./nuget.nix;

          projectFile = "<pname>.csproj";

          # Avoid HOME-related issues in the Nix sandbox — the .NET CLI writes
          # cache and config to $HOME/.dotnet by default, which is read-only
          # during the build. Redirect to a writable temp directory.
          DOTNET_CLI_HOME = "$TMPDIR/dotnet-cli-home";

          nativeBuildInputs = [ pkgs.dotnet-sdk_8 ];
          buildInputs =
            [ ]
            ++ pkgs.lib.optionals pkgs.stdenv.isDarwin [
              # .NET on Darwin needs Security and CoreFoundation for TLS,
              # certificate validation, and keychain access.
              pkgs.darwin.apple_sdk.frameworks.Security
              pkgs.darwin.apple_sdk.frameworks.CoreFoundation
            ];
          meta = {
            description = "<Project description>";
            homepage = "https://github.com/$UPSTREAM_OWNER/$UPSTREAM_REPO";
            license = pkgs.lib.licenses.<spdx>;
            mainProgram = "<binary-name>";
          };
        };
      in
      {
        packages = {
          # Users naturally try .#<pname>, so expose it alongside default.
          <pname> = <pname>;
          default = <pname>;
          source = <pname>;
        };

        apps = {
          <pname> = {
            type = "app";
            program = "${<pname>}/bin/<binary-name>";
          };
          default = {
            type = "app";
            program = "${<pname>}/bin/<binary-name>";
          };
        };

        overlays.default = final: prev: {
          <pname> = <pname>;
        };

        checks = {
          build = <pname>;
        };

        devShells.default = pkgs.mkShell {
          nativeBuildInputs = [ pkgs.dotnet-sdk_8 ];
          buildInputs =
            [ ]
            ++ pkgs.lib.optionals pkgs.stdenv.isDarwin [
              pkgs.darwin.apple_sdk.frameworks.Security
              pkgs.darwin.apple_sdk.frameworks.CoreFoundation
            ]
            # Add runtime service deps detected by:
            #   scripts/detect-runtime-deps.sh <project-dir>
            # Common examples: pkgs.surrealdb, pkgs.postgresql, pkgs.redis
            ++ [ <runtime-deps> ];
        };
      }
    );
}
```

## NuGet lockfile (`nuget.nix`)

`buildDotnetModule` requires a `nuget.nix` lockfile that pins every NuGet
dependency to a Nix store path. This is the .NET equivalent of `Cargo.lock` /
`cargoHash` and must be generated before the flake will build.

### Two-step process

1. **Enable NuGet lock files in the project.** Add
   `<RestoreLockMode>all</RestoreLockMode>` to a `<PropertyGroup>` in the
   `.csproj` (or `.fsproj`), then run `dotnet restore` — this produces
   `packages.lock.json` next to the project file:

   ```xml
   <Project Sdk="Microsoft.NET.Sdk">
     <PropertyGroup>
       <TargetFramework>net8.0</TargetFramework>
       <RestoreLockMode>all</RestoreLockMode>
     </PropertyGroup>
   </Project>
   ```

2. **Generate `nuget.nix`** from the lock file. Install `nuget-to-nix` (from
   `nixpkgs#nuget-to-nix`), then from the project root run:

   ```bash
   nix run nixpkgs#nuget-to-nix -- > nuget.nix
   ```

   This reads `packages.lock.json` (or `packages.config` for older SDK-style
   projects), fetches each package, and emits a Nix expression mapping package
   identifiers to store hashes. Commit `nuget.nix` alongside `flake.nix`.

When NuGet dependencies change, re-run both steps: `dotnet restore` to refresh
`packages.lock.json`, then `nuget-to-nix > nuget.nix` to regenerate the lockfile.

## `DOTNET_CLI_HOME`

The .NET CLI writes first-run telemetry, SDK caches, and tool manifests to
`$HOME/.dotnet` by default. Inside the Nix sandbox, `$HOME` is typically
read-only or unset, causing build failures with messages like
*"Access to the path '/homeless-shelter/.dotnet' is denied."*

Setting `DOTNET_CLI_HOME = "$TMPDIR/dotnet-cli-home";` in the derivation
redirects all of this to a writable temp directory, avoiding the issue entirely.
This is required for reproducible builds and should always be included.

## `dotnet-runtime` vs `dotnet-sdk`

- **`dotnet-sdk`** — includes the compiler, MSBuild, NuGet, and the runtime.
  Used for *building*. This is what goes in `nativeBuildInputs` and the
  `dotnet-sdk` parameter of `buildDotnetModule`.
- **`dotnet-runtime`** — just the execution runtime (CLR, base class library).
  Used for *running* a built application.

`buildDotnetModule` handles this distinction automatically: it uses the SDK to
build and wraps the output so the correct runtime is available at execution
time. However, if the project is a **library** (not a self-contained app), the
build output is a `.dll` that requires `dotnet-runtime` to be present in the
caller's environment. In that case, add `dotnet-runtime` to the package's
`propagatedBuildInputs` so downstream consumers get it transitively:

```nix
propagatedBuildInputs = [ pkgs.dotnet-runtime_8 ];
```
