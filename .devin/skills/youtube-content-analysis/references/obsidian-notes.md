# Obsidian Note Generation

Generate per-video Obsidian notes from a processed (deduplicated) YouTube
transcript. Each video gets its own directory containing a transcript note
(with timestamped deep-links into the video) and a separate summary note.

## Why Not a Subtitle Format?

No standard subtitle format (SRT, VTT, ASS/SSA) supports embedded hyperlinks.
WebVTT (W3C standard) is the closest — it supports timing, text, chapters, and
metadata — but its cue payload explicitly forbids `<` except for a fixed set of
inline tags (`<i>`, `<b>`, `<u>`, `<c>`, `<v>`, `<lang>`); there is no `<a>`
hyperlink tag in the spec. Markdown with YouTube timestamp URLs
(`https://youtu.be/<id>?t=<seconds>`) is the right choice for Obsidian notes —
it gives clickable deep-links into the video, which is the whole point.

## Directory Structure

One directory per video, containing the transcript and the summary as separate
notes:

```
<output-dir>/<video-slug>/
  transcript.md   # Deduplicated transcript with timestamp deep-links (TOON table)
  notes.md        # LLM-generated summary / synthesis
```

The `<video-slug>` is derived from the video title: lowercase, hyphens for
spaces, stripped of punctuation. Example: "Debugging in Production — A
7-Step Framework" → `debugging-in-production-a-7-step-framework`.

### Why a Directory Per Video?

- Scales to additional files (metadata, clips, annotations, screenshots)
  without cluttering the output directory
- Keeps all artifacts for one video together — easy to move, archive, or share
- The transcript and summary serve different purposes (raw data vs.
  synthesis) and mixing them in one note makes both harder to read

## transcript.md

Generated by `scripts/vid-transcripts.py --format obsidian`. The file
contains:

1. **YAML frontmatter** — `title`, `source`, `video_id`, `lang`,
   `fetch_date`
2. **Source link** — clickable URL to the video
3. **Chapters section** (if chapters are available) — bulleted list of
   `[HH:MM:SS](url?t=sec) Chapter Title` entries
4. **Transcript section** — an embedded TOON table with 9 columns

### TOON Column Schema

```
segments[N|]{idx|start|end|duration|text|link|chapter|speaker|lang}:
  1|00:00:01|00:00:04|3.0|"text here"|https://youtu.be/abc?t=1|Intro|Speaker A|en
```

| Column   | Description |
|----------|-------------|
| `idx`    | 1-based cue index — for cross-referencing from notes.md |
| `start`  | Start time (HH:MM:SS) |
| `end`    | End time (HH:MM:SS) |
| `duration` | Duration in seconds (float, 2 decimal places) |
| `text`   | Deduplicated transcript text for this segment |
| `link`   | YouTube deep-link (`https://youtu.be/<id>?t=<seconds>`) |
| `chapter`| Chapter name containing this cue's start time (empty if no chapters) |
| `speaker`| Speaker name from VTT `<v>` tags (empty if not present) |
| `lang`   | Language code (e.g., `en`, `es`, `fr`) |

### Generating transcript.md

```bash
# Download the VTT (yt-dlp)
yt-dlp --write-auto-sub --sub-lang en --skip-download -o '%(title)s' <url>

# Fetch metadata (for chapters and title)
yt-dlp --dump-json <url> > video.info.json

# Generate the Obsidian transcript note
python3 scripts/vid-transcripts.py --format obsidian \
  --video-id <VIDEO_ID> \
  --title "Video Title" \
  --info-json video.info.json \
  captions.en.vtt \
  <output-dir>/<video-slug>/transcript.md
```

The `--info-json` file provides:
- The `chapters` array (structured chapter data from YouTube) — used first
- The `description` field — parsed for chapter timestamps as a fallback when
  the `chapters` array is empty

Chapter resolution order:
1. `chapters` array in the info-json (structured, most reliable)
2. Description timestamp lines (`0:00 Intro`, `5:30 Topic`, ...) — fallback

These are not the same source: a video can have YouTube API chapters without
description timestamps, and vice versa. The info-json from `--dump-json`
includes both, so one yt-dlp call covers both sources.

## notes.md

The summary note is LLM-generated from the transcript. It is **not** produced
by `vid-transcripts.py` — the agent reads `transcript.md` (or the TOON data
directly) and writes the summary.

### Structure

```markdown
---
title: "Video Title — Notes"
source: "https://www.youtube.com/watch?v=<id>"
video_id: "<id>"
date: "2026-08-05"
---

# Video Title — Notes

## Summary

One-paragraph synthesis of the video's main argument or content.

## Key Points

- **[00:12](https://youtu.be/<id>?t=12)** First key point with timestamp link
- **[05:30](https://youtu.be/<id>?t=330)** Second key point with timestamp link

## Detailed Notes

### Chapter: Intro (00:00–05:30)

Notes on this chapter's content, with inline timestamp links where useful.

### Chapter: Main Topic (05:30–10:15)

More notes...

## Linked Assets

(If the video description links to recoverable assets — see INSTRUCTIONS.md
Description Asset Inlining section)

## Missing Visual Content Warnings

(If the transcript references visual content not recoverable from audio — see
INSTRUCTIONS.md Missing Visual Content Detection section)
```

### Cross-Referencing the Transcript

When referencing a specific moment in the transcript, use the cue `idx` from
the TOON table. Example: "See transcript cue #15 for the exact wording" or
link directly to the timestamp: `[cue #15](https://youtu.be/<id>?t=125)`.

### What Goes in notes.md vs. transcript.md

| Aspect | transcript.md | notes.md |
|--------|---------------|----------|
| Purpose | Raw data (deduplicated, structured) | Synthesis (understandable, actionable) |
| Format | TOON table (machine-readable) | Prose + bullets (human-readable) |
| Timestamps | Every cue has start/end/duration/link | Only at key points |
| Length | Full transcript | Condensed summary |
| Generated by | `vid-transcripts.py` | LLM (the agent) |
| Missing visual content | Not applicable | Warnings section at bottom |
| Linked assets | Not applicable | Inlined or linked |
