# Boilerplate Version Updates

Refresh every **already-pinned** version in this repo to the latest stable release, using **live queries to the actual package registries** — never your own knowledge — and enforce that all TypeScript/JavaScript templates resolve dependency versions through `pnpm-workspace.yaml` catalogs.

## Hard rules

- **No version from memory.** Every proposed version must come from a registry/tool query executed in this session. Record the exact command and its output in the final report. If a query fails, do not guess — mark the entry `QUERY-FAILED` in the report.
- **Only update entries that already specify a concrete version.** Do NOT pin entries that are intentionally floating: `""` in devbox.json, `latest`, `@master`/`@main` action refs, unpinned deps. List them in the report as `floating (unchanged)`.
- **Preserve the existing version-spec style.** `^x.y.z` stays `^`-ranged, `>=x` stays a floor, exact pins stay exact, `v`-prefixed tags keep the `v`, major-only pins (e.g. `go 1.21`, `node:22-alpine`, `.nvmrc` = `26`) stay major-only.
- **Stable releases only.** Skip prerelease/beta/nightly versions unless the current pin is already a prerelease (e.g. `skills-detector: ^0.0.1-security` — leave or query for a newer `-security` build only).
- **Write shared content in `_shared/` only.** `partials.bak/` is regenerated by `./copier-wrapper.sh`; never edit it.
- **Preserve Jinja.** Files ending `.jinja` contain `{% ... %}`/`{{ ... }}` — update only the version literals, keep conditionals/includes intact.
- **npm registry queries:** `pnpm` has no `view`/`info` subcommand; use `npm view` (read-only) or `curl` to `registry.npmjs.org`. The repo rule against `npm`/`npx` applies to installing/executing packages — read-only metadata queries are fine.
- **High-risk pins — confirm before bumping:** `nixpkgs.commit` (global nix package set; the x86_64-darwin pin exists for Intel-Mac compat), `mcr.microsoft.com/playwright` (must match `@playwright/test` catalog version), language `*_version` copier defaults that gate generated-project minimums. Apply other majors freely but flag them in the report.

## Step 1 — Inventory all pinned versions

Search the repo for every location that carries a concrete version. Expected locations:

| Where | Pattern |
|---|---|
| pnpm catalog (single source for npm deps) | `_shared/partials/pnpm-workspace-partials/catalog.yaml.jinja`, plus any inline `catalog:`/`catalogs:` blocks in `**/pnpm-workspace.yaml*` |
| package.json | `packageManager`, `engines`/`devEngines`, and any dep NOT using `"catalog:"` — `**/package.json*` |
| devbox | `**/devbox.json*` and `_shared/partials/devbox-partials/*` — entries `"pkg": "x.y.z"` (non-empty string) or `"version": "..."`; plus `nixpkgs.commit` (high-risk, see rules) |
| Dockerfiles | `FROM image:tag`, `ARG`/`ENV` version vars, `npm i -g x@y`, `curl .../vX.Y/...` — `**/Dockerfile*`, `.devcontainer/` |
| GitHub Actions | `uses: owner/repo@tag` — `**/.github/workflows/*`, `_shared/dot_github/workflows/` |
| pre-commit hooks | `rev:` — `_shared/partials/pre-commit/`, `**/.pre-commit-config*` |
| copier.yml | `*_version:` defaults (`node_version`, `python_version`, `go_version`, `java_version`, `maven_version`, `kotlin_version`, `dotnet_version`, `ruby_version`, `powershell_version`, `pnpm_version`, `postgres_version`, ...) and `_min_copier_version` |
| Python | `**/requirements*.txt*`, `**/pyproject.toml*` (`dependencies`, `requires-python`, `[tool.*]` pins) |
| Rust | `**/Cargo.toml*` — `[dependencies]`/`[build-dependencies]`/`[dev-dependencies]` version fields |
| Go | `**/go.mod*` — `go X.Y` directive and `require vX.Y.Z` |
| JVM | `**/pom.xml*`, `**/build.gradle.kts*`, `**/gradle.properties*` |
| .NET | `**/*.csproj*` — `TargetFramework`, `PackageReference Version=` |
| Ruby | `**/Gemfile*` — `ruby "x.y"`, gem pins |
| Swift | `**/Package.swift*` — `swift-tools-version`, `.package(... from: "x.y")` |
| Node runtime | `_shared/dot_nvmrc.jinja`, `**/.nvmrc*` |

## Step 2 — Query each registry live

Use the command for the ecosystem. Batch queries per ecosystem; keep a scratch list of `name → latest`.

**npm (pnpm catalog, package.json, packageManager field):**
```bash
npm view <pkg> version                                          # latest stable
npm view <pkg> dist-tags --json                                 # see all dist-tags
# or without npm:
curl -s https://registry.npmjs.org/<url-encoded-name>/latest | jq -r .version
# scoped names are encoded as @scope%2Fname, e.g. @nx/next -> @nx%2Fnext
```

**PyPI** (`requirements*.txt`, `pyproject.toml`, `_min_copier_version`):
```bash
curl -s https://pypi.org/pypi/<pkg>/json | jq -r .info.version
```

**crates.io** (`Cargo.toml`):
```bash
curl -s -H 'User-Agent: levonk-base-boilerplate (version audit)' \
  https://crates.io/api/v1/crates/<crate> | jq -r .crate.max_stable_version
```

**Go modules** (`go.mod`):
```bash
go list -m -json <module>@latest | jq -r .Version
# or: curl -s https://proxy.golang.org/<module>/@latest | jq -r .Version
# module paths with uppercase letters must be !-escaped per the GOPROXY protocol
go list -m -versions go | tail -1    # for the `go X.Y` directive
```

**Docker Hub / MCR** (`FROM` tags — keep the same variant suffix like `-alpine`/`-slim`/`-jammy`):
```bash
skopeo list-tags docker://<image>          # or: crane ls <image>
curl -s "https://hub.docker.com/v2/repositories/<ns>/<image>/tags?page_size=100" | jq -r '.results[].name'
curl -s https://mcr.microsoft.com/v2/<repo>/tags/list | jq -r '.tags[]'   # mcr.microsoft.com images
```

**GitHub Actions + pre-commit `rev:`** (`uses:`, `repo:` URLs):
```bash
gh api repos/<owner>/<repo>/releases/latest --jq .tag_name
gh api repos/<owner>/<repo>/tags --jq '.[].name' | head -20   # for major-tag style pins (@v4)
git ls-remote --tags https://github.com/<owner>/<repo>        # no-gh fallback
```

**devbox / nix packages** (only non-`""` version strings):
```bash
devbox info <pkg>    # lists versions available on nixhub
```

**Maven Central** (`pom.xml`, `build.gradle.kts`):
```bash
curl -s "https://search.maven.org/solrsearch/select?q=g:%22<groupId>%22+AND+a:%22<artifactId>%22&core=gav&rows=1&wt=json" \
  | jq -r '.response.docs[0].latestVersion'
```

**NuGet** (`*.csproj`):
```bash
curl -s https://api.nuget.org/v3-flatcontainer/<package-id-lowercase>/index.json | jq -r '.versions[-1]'
```

**RubyGems** (`Gemfile`):
```bash
curl -s https://rubygems.org/api/v1/versions/<gem>/latest.json | jq -r .version
```

**Language/runtime release lines** (`.nvmrc`, `*_version` copier defaults, `requires-python`, `TargetFramework`, `swift-tools-version`, `go` directive):
```bash
curl -s https://endoflife.date/api/<product>.json | jq -r '.[0:5][] | .cycle'   # node, python, go, ruby, dotnet, java, kotlin, powershell, swift
curl -s https://nodejs.org/dist/index.json | jq -r '[.[] | select(.lts != false)][0].version'
curl -s https://go.dev/dl/?mode=json | jq -r '.[0].version'
```
Match the granularity already in the file (major-only `26` in `.nvmrc` → latest major; `8.0` TargetFramework → latest LTS band).

## Step 3 — Apply updates

- Fix `_shared/` partials **first** — one edit propagates to every template that includes them.
- Then per-template files that carry their own pins.
- Keep indentation, comments, and Jinja blocks untouched; change only the version literal.
- For Dockerfiles, bump the tag but keep the variant (`node:22-alpine` → `node:<latest-major>-alpine`).
- For GitHub Actions pinned to a major tag (`@v4`), move to the newest **major tag** if a newer major exists, else leave.
- Consistency pass: the same package must resolve to the same version everywhere it's pinned (e.g. `typescript` in the catalog vs any inline pin, `node` version across `.nvmrc`/Dockerfile/`engines` floor vs `devEngines`).

## Step 4 — Enforce pnpm catalogs for all TS/JS templates

pnpm catalogs are the repo's version mechanism for npm deps: versions live in `pnpm-workspace.yaml` under `catalog:` (and optionally named `catalogs:`), and `package.json` deps reference them as `"catalog:"`. The shared catalog is `_shared/partials/pnpm-workspace-partials/catalog.yaml.jinja`, included via `{% include "partials.bak/partials/pnpm-workspace-partials/catalog.yaml.jinja" %}`.

For every template directory containing a `package.json`/`package.json.jinja`:

1. **A `pnpm-workspace.yaml(.jinja)` must exist alongside it** with a `catalog:` section (usually the shared include, plus template-local keys when needed). Create it if missing — even single-package templates, since `catalog:` only resolves through `pnpm-workspace.yaml`.
2. **No inline semver in `dependencies`/`devDependencies`.** Every entry must be `"catalog:"` (default catalog) or `"catalog:<name>"` (named catalog). Exceptions: `"workspace:*"`, `"file:"`, `"link:"` refs. Move any stray inline version into the appropriate catalog.
3. **Every `"catalog:"` reference must resolve.** Collect all `catalog:` keys referenced by the template's package.json files and verify each exists as a key in the template's effective catalog (shared partial + local block). Add missing keys with live-queried versions — prefer adding to the shared catalog when the dep is used by 2+ templates, otherwise a template-local `catalog:`/`catalogs:` entry.
4. **`packageManager` field** → latest pnpm from Step 2 (`npm view pnpm version`).
5. **Catalog values** → refresh each entry's version from the npm queries; keep the `^` range style already in use.

## Step 5 — Verify

- Parse-check every edited file: `jq . <file>` for JSON (strip Jinja first where needed), `yq . <file>` for YAML.
- Re-grep for `catalog:` refs with no matching catalog key (Step 4.3).
- Re-grep for leftover inline versions in package.json deps: `"[^"]+":\s*"[\^~>=]*[0-9]` inside `dependencies`/`devDependencies`.
- Render at least one updated template end-to-end: `devbox run -- rtk ./copier-wrapper.sh copy <template> /tmp/render-check --data @/tmp/answers.yml --defaults` and confirm the generated `pnpm-workspace.yaml`/lockfile resolution works (`pnpm install --lockfile-only` inside the render when feasible).
- `git diff` review: confirm no `""`→pinned conversions, no Jinja breakage, no variant suffixes changed.

## Step 6 — Report

Produce a table for the user:

```
| file | package/tool | old | new | query used | notes |
```

Plus separate lists for: `floating (unchanged)` entries, `QUERY-FAILED` entries, applied major-version bumps, high-risk pins awaiting confirmation, and catalog keys added/created.
